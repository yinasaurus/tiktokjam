Slide 1: The Project In One Table

QuestionSimple answer
What are we building?A shopping copilot that asks useful questions and recommends product IDs.
What is the data?A frozen Amazon Reviews 2023 clothing catalog with 50,000 products.
What does the judge score?Whether the hidden target product appears in our Top 10, how high it ranks, and how fast we find it.
Do we use paid API calls?No. The submitted path is offline and reports zero token usage.

Slide 2: Why This Is Hard

Customer behaviorProblemOur response
Vague browsingThe first message may not contain enough detail.Ask one attribute question and still return Top 10 candidates.
High-intent buyingHard constraints like material or color matter immediately.Use category and exact constraints early.
Intent overrideThe customer changes their mind mid-session.Replace old constraints instead of mixing old and new intent.
Boundary responseThe customer says they have no preference.Do not get stuck; move to another useful attribute.

Slide 3: Scoreboard Meaning

CoverageHitRate@10

Did we include the right product in the 10 answers?

PrecisionMRR

If we found it, did we put it near rank 1?

EfficiencyMTTC

How many turns did we need before conversion?

TechnicalScore = 0.50 * HitRate@10 + 0.30 * MRR + 0.20 * Efficiency

Slide 5: What Are We Actually Using?

QuestionAnswer
Are we using an LLM?No hosted LLM is used in the submitted default. No paid API call is required.
Are we using BM25?BM25 means keyword search. We tested BM25-style/hybrid code, but the default is not plain BM25.
What is ranked retrieval?Give each candidate product a score, sort by that score, and return the best 10 IDs.
What is the main search method?Category filtering, exact disclosed constraints, lexical/token overlap, and popularity fallback.
Are we training a model?Not for the submitted default. LightGBM training is a research branch only.
Why this method?It is faster, cheaper, reproducible, and currently beats the heavier research path.
